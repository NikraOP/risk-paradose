# AFTERFALL

Браузерный 2D roguelite с видом сверху и управлением для телефона. Самостоятельная игра, вдохновлённая циклом Risk of Rain: время усиливает врагов, предметы складываются, телепорт вызывает босса. Оригинальные названия, мир и процедурная графика.

## Играть

После включения GitHub Pages: https://nikraop.github.io/risk-paradose/

Репозиторий подготовлен для публикации из `main`, каталог `/docs`. В Settings → Pages → Build and deployment выбрать **Deploy from a branch**, затем **main /docs** и Save. Сборка и npm-зависимости не нужны.

## Управление

| Действие | Телефон | Компьютер |
| --- | --- | --- |
| Движение | Джойстик слева | WASD / стрелки |
| Стрельба | Автоматически в ближайшего врага | Автоматически |
| Рывок | ↯ | Space |
| Импульс | ✳ | Q |
| Сундук / телепорт | Контекстная кнопка | E |
| Пауза | Ⅱ | Escape / P |

Удерживай джойстик и одновременно используй способности. Рывок даёт короткую неуязвимость; импульс наносит урон вокруг и уничтожает ближайшие вражеские снаряды. Звук включается кнопкой ♪.

## Цикл экспедиции

1. Уничтожай врагов; собирай зелёные кристаллы опыта и получай золото.
2. При повышении уровня выбирай один из трёх случайных артефактов. Покупай дополнительные артефакты в сундуках. Повторные предметы усиливают эффект.
3. Найди телепорт, активируй его и победи стража. Для зарядки проведи суммарно 40 секунд внутри круга; вне круга зарядка останавливается.
4. Когда зарядка завершена и страж побеждён, подойди к центру и перейди дальше.
5. Пройди три сектора. После последнего телепорта — победа; после смерти — новая экспедиция.

### Реализовано

- Три сектора: Забытая долина, Холодный предел, Сердце разлома.
- Три обычных типа врагов и страж с круговыми атаками.
- Восемь складывающихся артефактов: урон, скорость, скорострельность, здоровье, регенерация, дополнительные снаряды, магнит и усиление импульса.
- Рост сложности со временем, сундуки, выбор улучшений и два активных умения.
- Сенсорный мультитач, клавиатура, портретная и альбомная компоновки.
- Пауза при потере фокуса; лучший результат сохраняется локально.
- Частицы, свечение, дождь, динамический бой, процедурное окружение, синтезированные звуки.

## Локальный запуск и проверки

Из корня репозитория:

```sh
python3 -m http.server 8000 --directory docs
```

Открыть http://localhost:8000. ES-модулям нужен HTTP-сервер; двойной щелчок по HTML не заменяет запуск сервера.

Проверки (Node.js 20+):

```sh
npm test
npm run check
```

Тесты проверяют нормализацию движения, паузу, неуязвимость и перезарядку, автострельбу и награды, оплату сундуков, импульс, выбор и накопление улучшений, условия зарядки, переходы, победу, смерть и столкновения. Отдельный smoke-тест выполняет отрисовку и сенсорные обработчики с моделью DOM; это не замена тесту на физическом телефоне.

### Ограничения первой версии

Это законченная компактная экспедиция, а не воспроизведение всего контента Risk of Rain. Один герой, три сектора, без сетевой игры и сохранения незавершённого забега. Процедурная графика рисуется Canvas 2D; производительность на физических iOS/Android-устройствах ещё требует проверки. Интерфейс использует необязательные Google Fonts с системными запасными шрифтами. Звуки работают после взаимодействия пользователя и включения звука.

## README для дальнейшей разработки

### Рабочий промпт

> Развивай AFTERFALL как мобильный браузерный roguelite. Сначала прочитай README и существующий код. Результат должен быть играбельной игрой: исследование → бой → усиление → босс → переход. Сохраняй вид сверху, управление одним джойстиком, автострельбу и активные способности. Делай разумные технические решения самостоятельно. Изменяй только то, что нужно для текущей задачи. Проверяй воспроизводимые игровые сценарии и сообщай отдельно о проверенном поведении и непроверенных предположениях. Заканчивай рабочими файлами и доступным способом запуска.

### Правила работы

1. **Результат.** Сначала определить, что игрок сможет сделать после изменения; сформулировать критерий готовности.
2. **Контекст.** Читать только нужные модули. Логика — `docs/engine.mjs`; изображение — `docs/renderer.js`; интерфейс, звук и ввод — `docs/game.js`; компоновка — `docs/style.css`.
3. **Мобильность.** Не блокировать одновременное движение и способности. Обрабатывать `pointercancel`, потерю фокуса и смену размеров. Не допускать прокрутки игровой поверхности.
4. **Механика.** Движение должно зависеть от времени, диагонали не должны ускорять героя, пауза должна останавливать симуляцию. Условия победы, смерти и телепорта должны быть явными.
5. **Читаемость.** Герой, угрозы, снаряды и интерактивные объекты различимы на маленьком экране. Боевые эффекты не закрывают управление.
6. **Производительность.** Кэшировать статичную землю, отсекать невидимые объекты, ограничивать число частиц и врагов. Сохранять пространственные корзины для проверки попаданий.
7. **Проверка.** Использовать детерминированный seed для воспроизведения ошибок. Добавлять регрессионный тест для изменённого риска. Не называть статический анализ проверкой на реальном устройстве.
8. **Поставка.** Сохранять относительные ссылки, чтобы работал подкаталог GitHub Pages. Не добавлять ключи, учётные данные и служебную конфигурацию окружения в публичный репозиторий.

### Как формулировать следующую задачу

Указать **цель → контекст → ограничения → критерии готовности**. Это рабочая структура, а не обязательная «магическая» формула. Она основана на [официальном руководстве по промптам OpenAI](https://learn.chatgpt.com/docs/prompting).

Пример:

> Добавь второго героя с дробовиком. Сохрани существующее управление и цикл экспедиции. Выбор героя должен менять оружие и характеристики. Готово, когда обоими героями можно начать забег, пользоваться способностями и пройти телепорт. Проверь, что выбор не теряется между секторами.

Для браузерной реализации применяются подходящие навыки создания сайтов; для проверки руководств — OpenAI Docs. Новые зависимости и плагины нужны только при конкретной нехватке возможностей.
